## How a status is decided

- `SUPPORTED`: a provider adapter collected a complete, repeatable listing from a documented public endpoint, with stable posting ids and direct HTTPS application links.
- `SUPPORTED_UNDOCUMENTED`: the same evidence from a public endpoint that the provider does not document.
- `HTML_ONLY`: the careers page publishes structured job documents (JSON-LD `JobPosting`) and no feed, so it needs an HTML adapter.
- `FALLBACK_ONLY`: the official careers page answered, but publishes no provider feed and no machine-readable job document over ordinary HTTP, so covering it needs a fallback source.
- `BLOCKED`: the page refused access or served a challenge at audit time. The audit never attempts to defeat a challenge.
- `NEEDS_MANUAL_REVIEW`: the evidence was ambiguous, the page could not be read, or a recognised enterprise provider (Workday, SuccessFactors, iCIMS, Eightfold, Oracle) has no adapter yet, so completeness, stable identity, and direct links stay unproven.

An HTTP 200 alone never earns a supported status, and no company is assigned a provider from reputation or from an unverified third-party directory.
